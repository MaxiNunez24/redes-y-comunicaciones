# Práctica 2 - Capa de Aplicación (HTTP)

## Introducción

### 1. ¿Cuál es la función de la capa de aplicación?
Las funciones de la capa de aplicación son:
- Proveer servicios de comunicación a los usuarios (Conocidos como Capa 8) y a las aplicaciones, incluye las aplicaciones mismas.

- Proveer servicios de comunicación en el modelo Machine to machine (M2M), sin usuarios (personas)

- Brindar una Interfaz con el usuario, User Interface (UI), o una Interfaz con las aplicaciones, Application Programming Interface (API).

- Tanto las aplicaciones que usan la red como los protocolos que implementan las aplicaciones pertenecen a esta capa. 

- Existen aplicaciones que NO son de red que deberan trabajar con aplicaciones de red, por ejemplo, un procesador de texto que permite enviar documentos por correo electrónico.

### 2. Si dos procesos deben comunicarse:
#### a. ¿Cómo podrían hacerlo si están en diferentes máquinas?
Si dos procesos que deben comunicarse están en diferentes máquinas, podrían hacerlo a través de la red utilizando protocolos de comunicación como TCP/IP. Esto implica que cada proceso debe tener una dirección IP y un puerto asignado para establecer la conexión. Los procesos pueden enviar y recibir datos mediante sockets, que son puntos finales de comunicación en la red. Además, podrían utilizar protocolos de aplicación específicos, como HTTP, FTP o SMTP, dependiendo del tipo de comunicación que necesiten realizar.
#### b. Y si están en la misma máquina, ¿qué alternativas existen?
Si los procesos están en la misma máquina, existen varias alternativas para que puedan comunicarse entre sí:
- **Pipes (Tuberías)**: Permiten la conmunicación entre procesos mediante un flujo de datos unidireccional.
- **Sockets locales (Unix Domain Sockets)**: Permiten la comunicación entre procesos en la misma máquina utilizando la pila de red, pero sin salir al exterior.
- **Memoria compartida**: Permite que varios procesos accedan a una misma región de memoria para intarcambiar datos de manera eficiente.
- **Señales (Signals)**: Permiten que un proceso envíe notificaciones a otro proceso para indicar que ha ocurrido un evento.
- **Colas de mensajes (Messsage Queues)**: Permiten que los procesos envíen y reciban mensajes de manera asincrónica.

### 3. Explique brevemente cómo es el modelo Cliente/Servidor. Dé un ejemplo de un sistema Cliente/Servidor en la “vida cotidiana” y un ejemplo de un sistema informático que siga el modelo Cliente/Servidor. ¿Conoce algún otro modelo de comunicación?
El modelo Cliente/Servidor es similar a un Request/Response sin estados o stateless. En este modelo, un cliente realiza solicitudes a un servidor, que procesa esas solicitudes y devuelve una respuesta al cliente. El servidor es responsable de manejar múltiples clientes simultáneamente y proporcionar los recursos o servicios solicitados.
